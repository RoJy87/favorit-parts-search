# Проценка автозапчастей

Клиентское приложение для подбора автозапчастей и аналогов через Web-сервис «Проценка»
(Favorit Parts). Поиск выполняется в два этапа: артикул → производители → аналоги и
предложения складов.

## Стек

- React 18 + Redux Toolkit (`createSlice`, `createAsyncThunk`) + `react-redux`
- Vite
- Bootstrap 5 (только CSS, без JS-плагинов)
- JavaScript, без TypeScript

## Запуск

```bash
npm install
cp .env.example .env
npm run dev
```

Приложение поднимается на http://127.0.0.1:5173.

Сборка:

```bash
npm run build
npm run preview
```

### Ключ доступа

Ключ покупателя и адрес сервиса задаются в `.env`:

```
VITE_WSPRICE_KEY=<ключ покупателя>
VITE_WSPRICE_URL=https://api.favorit-parts.ru/hs/hsprice/
```

Без `.env` используется демонстрационный ключ из документации к сервису — на нём действует
ограничение по числу запросов.

## Как работает

1. **Поиск производителей.** Ввод артикула (минимум 2 символа) → запрос
   `?key=…&number=…&info=on`. Сервис возвращает позиции с этим номером и названиями
   производителей. Ответ показывается таблицей: производитель, наименование, артикул,
   цена от, остаток.
2. **Аналоги и предложения.** Клик по производителю → запрос
   `?key=…&number=…&brand=…&analogues=on&info=on`. Из ответа берётся массив `analogues`
   выбранной позиции и выводится таблицей: производитель, наименование, артикул,
   стоимость, остаток. Строка выбранной детали закреплена сверху.
3. **Детализация по складам.** Для каждой позиции раскрывается список предложений:
   склад, цена, остаток, дата и время отгрузки, признак «свой склад/поставщик»,
   признак невозвратной позиции.

## Решения по реализации

- **Дебаунс и отмена запросов.** Поиск идёт по мере ввода с паузой 450 мс, предыдущий
  запрос отменяется через `AbortController`. У сервиса есть лимит запросов на клиента,
  поэтому набираемый артикул не должен превращаться в запрос на каждый символ:
  при вводе «01089» уходит один запрос, а не пять.
- **Цена берётся из предложений складов.** В ответе есть поле `goods.price`, но в
  документации оно помечено как оставленное для совместимости: у части позиций оно нулевое
  или устаревшее. Стоимость позиции считается как минимальная цена среди складов,
  остаток — из `count`.
- **Пустой ответ.** Если деталь не найдена, сервис возвращает массив с одной пустой
  структурой (`brand: ""`, нулевой `goodsID`). Такие элементы отфильтровываются, иначе в
  списке появляется пустая строка, а состояние «ничего не найдено» не отображается.
- **Ошибки API.** Ошибки приходят с HTTP 403 и телом `{"error": "…"}`, поэтому тело
  разбирается в первую очередь, а не статус ответа. Известные ошибки (`Empty key!`,
  `Invalid key client!`, `Request quota exceeded!`) переводятся в понятный текст,
  остальные показываются как есть. Сбой сети отличается от ошибки сервиса.
- **Состояния интерфейса.** На каждом этапе — свой лоадер; ошибка показывается алертом с
  кнопкой «Повторить»; «ничего не найдено» и «нет позиций в наличии» — разные пустые
  состояния.
- **Признак невозвратной позиции.** Передаётся `info=on`, в таблицах показываются бейджи
  «невозврат» на уровне позиции и склада.

## Структура

```
src/
  api/wsprice.js            запросы к сервису и нормализация ответа
  store/index.js            конфигурация store
  store/partsSlice.js       состояние поиска и аналогов
  components/SearchForm.jsx форма поиска, дебаунс
  components/BrandsTable.jsx      таблица производителей (этап 1)
  components/AnaloguesTable.jsx   таблица аналогов и складов (этап 2)
  components/Status.jsx     лоадер, алерт ошибки, пустое состояние
  utils/format.js           форматирование цен, остатков и дат
```
